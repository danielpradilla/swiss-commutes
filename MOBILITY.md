# Shared mobility

`/swiss-commutes/mobility/` and `/mobility/<city>/` show reported vehicle availability for the same sixteen city views. The map starts at each city centre. Its right-hand list and total cover the current map bounds and selected vehicle types, not an administrative city boundary. Selecting a row pans to its marker. Palette blue indicates bikes, ochre scooters, teal cars and dark slate mopeds; the selectors use the same colours and name each type on hover or keyboard focus. The legend shows dot-size examples for 1, 10 and 30 available vehicles without repeating the selector colours. A mixed-type site takes the colour of its most available selected type (ties follow selector order). Dot radius grows with the square root of the selected available vehicle count, capped at 13 pixels from 49 vehicles onward. These are absolute counts, not occupancy percentages or a guarantee of a reservation.

## Source and interpretation

The [SFOE / sharedmobility.ch dataset](https://data.opentransportdata.swiss/dataset/sharedmobility) publishes participating providers' GBFS feeds. The page reads the public combined GBFS 2.0 `vehicle_types`, `free_bike_status`, `station_information`, and `station_status` files. For providers with multiple vehicle kinds at stations, it also reads their GBFS 2.3 `station_status` with `vehicle_types_available`; the combined `num_bikes_available` alone cannot distinguish bikes, scooters and cars. The provider-specific interface requires a valid email in its Authorization header; the documented example email is used. No API Manager key is needed.

`form_factor` selects the bike (including cargo bikes), scooter, car or moped icon. A fresh installed/renting station report supplies counts by type where possible. Station reports more than ten minutes old do not supply counts. An individually reported, unreserved and enabled vehicle at the exact coordinate of a known station uses its station name; it is not counted again when that station already has a fresh count. Other vehicles appear at their reported coordinates, not at artificial grid centres. Only vehicles from the same provider at identical coordinates share a street marker. The street list labels them with rounded coordinates; it does not invent a station name. Hovering a marker shows its location label, vehicle types, available count and provider. Stations without an unambiguous type or current count and vehicles without a recognised type are omitted. A missing marker does not establish that no rental vehicle is present.

The header shows the oldest `last_updated` timestamp among the four combined feeds. The browser polls once a minute while visible and refreshes when a hidden tab returns. Failed refreshes retain the last received snapshot with an error notice. The right list puts named stations first and displays at most 150 sites, stating when more are in the map view; zoom in to see the rest. The map still draws all matching sites.

## Server operation

`public/mobility/feed.php` is a same-origin pass-through for the four public combined files and allowlisted provider-specific station-status paths. The upstream combined endpoint sends duplicate CORS origin headers, so browsers cannot read it directly. The PHP endpoint validates JSON and retains each response for at least 60 seconds in a private cache with a separate lock per path. On source failure it serves the last valid copy; without a copy it returns 503. `SWISS_MOBILITY_CACHE_DIR` can set the cache location; otherwise it uses the PHP system temporary directory under `swiss-commutes-mobility`. Do not put this directory under the published tree. The cache contains public GBFS data, no credentials. The server needs PHP 8.2+ with cURL and outbound HTTPS access to `sharedmobility.ch`.

The PHP endpoint runs on request and needs no cron. Deploy `out/mobility/` with the rest of `out/`. Confirm `/mobility/feed.php?path=vehicle_types.json` returns JSON with `last_updated`, and open a city page to check the source time, named stations, selectors, list and map markers. `npm run test`, `npm run lint` and `npm run build` cover the local code and export. Next dev serves static pages but not PHP; exercise the exported page through a PHP-capable web server for a complete local smoke test.
